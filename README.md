# Backend API - Sistema de Gestión de Incidentes

Proyecto Spring Boot que implementa la API REST para el Sistema de Gestión de Incidentes solicitado en la Actividad #8. Usa una base de datos H2 embebida para desarrollo y pruebas.

## Resumen
- API REST para gestionar `tickets` (CRUD).
- Entidades mínimas: `id`, `titulo`, `descripcion`, `categoria`, `prioridad`, `estado`.
- Base de datos: H2 (in-memory/file) configurada en `application.properties`.

## Requisitos
- Java 17+ (o la JDK que uses; en este proyecto se probó con Temurin 25).
- Maven 3.6+

## Ejecutar la aplicación (desarrollo)
1. Desde la raíz del proyecto `backend-api` construir y ejecutar con Maven:

```bash
mvn clean package
mvn spring-boot:run
```

2. Alternativa: ejecutar el jar generado:

```bash
mvn package
java -jar target/backend-api-0.0.1-SNAPSHOT.jar
```

La API por defecto se sirve en `http://localhost:8080`.

## Endpoints
- `GET /tickets` — Listar todos los tickets.
- `GET /tickets/{id}` — Obtener ticket por `id`.
- `POST /tickets` — Crear nuevo ticket (JSON en body).
- `PUT /tickets/{id}` — Actualizar ticket.
- `DELETE /tickets/{id}` — Eliminar ticket.

## Estructura de la tabla/entidad `Ticket`
- `id` (Long / autogenerated)
- `titulo` (String)
- `descripcion` (String)
- `categoria` (ENUM: Red, Hardware, Software)
- `prioridad` (ENUM: Alta, Media, Baja)
- `estado` (ENUM: Abierto, En Progreso, Cerrado)

## Pruebas
- Usé Postman para probar los endpoints (status 200/201 en respuestas JSON).
- Exporta tu colección de Postman y colócala en `backend-api/docs/postman_collection.json` si quieres incluirla en el repositorio.
